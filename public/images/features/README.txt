รูปในโฟลเดอร์นี้คือ screenshot จริงจาก TradingView ใช้ในหน้า /features/<slug>
กำหนดที่ image: { src, width, height } ใน src/config/features.ts
ฟีเจอร์ที่ไม่ใส่ image จะถูกซ่อนจากเว็บทั้งหมด (ดูตัวกรอง hasScreenshot ในไฟล์นั้น)

━━ ขนาดที่ต้องใช้ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

กว้างอย่างน้อย  1140px   ให้คมบนจอปกติ
กว้างที่ควรได้  2280px   ให้คมบนจอ 2x ด้วย (Retina / โน้ตบุ๊กรุ่นใหม่ / มือถือ)

สัดส่วนอิสระ ไม่ต้องตัดเป็น 16:10 เหมือนแต่ก่อน หน้าเว็บปรับกรอบตามไฟล์ให้เอง
แต่ต้องกรอก width/height ใน features.ts ให้ตรงไฟล์เป๊ะ ไม่งั้นภาพจะถูกยืด
อ่านขนาดจริงจากไฟล์ด้วย  npm run images:sizes features
(คำสั่งนี้เตือนให้เองด้วยว่าไฟล์ไหนเล็กเกินไป)

ทำไมต้องใหญ่ขนาดนั้น
  หน้า /features/<slug> วางภาพกว้าง 1140px (ไม่ใช่ 768px ตามที่ max-w-3xl เขียนไว้
  — .container-x อยู่นอก @layer จึงชนะ utility ของ Tailwind ดูคอมเมนต์ในหน้านั้น)
  ไฟล์ที่เล็กกว่าช่องจะถูกเบราว์เซอร์ขยาย แล้วตัวหนังสือบนกราฟจะเบลอ
  รายละเอียดที่ไม่มีในไฟล์ต้นฉบับสร้างขึ้นมาไม่ได้ ต้อง export ให้ใหญ่ตั้งแต่แรก
  (เรื่องเดียวกับคลิป Hero ที่บันทึกไว้หัวไฟล์ src/config/guide.ts)

━━ ที่มาของรูป ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

- รุ่นแรก  ตัดจากคลิปที่แคปด้วยโหมด Bar Replay จึงมีลายน้ำ "การเล่นซ้ำ" จาง ๆ กลางภาพ
           ภาพต้นทางอยู่ที่ public/images/charts/ (smc-suite / gold-suite / ict-suite)
- รุ่นสอง  ตัดจากลิงก์ snapshot ของ TradingView (tradingview.com/x/...) ซึ่งไม่มีลายน้ำ
           ลงท้ายชื่อไฟล์ด้วย -snap เมื่อเป็นการแทนที่รูปรุ่นแรกของฟีเจอร์เดิม
           ไฟล์ต้นฉบับ 1814x921 เก็บไว้ที่ media-src/tradingview/ (ไม่เข้า git)

⚠️ ห้ามทับไฟล์ชื่อเดิมเมื่อเปลี่ยนรูปของฟีเจอร์ที่มีรูปอยู่แล้ว
Next.js แคชภาพที่ optimize แล้วตาม URL ทับชื่อเดิมจะยังได้ภาพเก่าทั้งบน dev และ production
ให้ตั้งชื่อใหม่แล้วแก้ path ใน features.ts แทน (เหตุผลเดียวกับหมายเหตุที่ tradingView.snapshotUrl ใน config/site.ts)

━━ วิธีตัดรูปใหม่ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  curl -o snap.png https://s3.tradingview.com/snapshots/<ตัวแรกพิมพ์เล็ก>/<id>.png
  ffmpeg -i snap.png -vf "crop=<w>:<h>:<x>:<y>" -c:v libwebp -quality 80 <slug>-v4.webp

เลือกกรอบให้เห็นฟีเจอร์นั้นชัด และเลี่ยงแกนเวลากับไอคอนปฏิทินเศรษฐกิจที่ขอบล่าง
ไม่ต้องใส่ scale= ถ้ากรอบที่ตัดกว้างเกิน 1140px อยู่แล้ว — ปล่อยความละเอียดเต็มไว้ดีกว่า
ถ้าจำเป็นต้องขยายเพราะต้นฉบับเล็ก ใช้ lanczos + unsharp อย่าปล่อยให้เบราว์เซอร์ขยายเอง
  scale=<w>:<h>:flags=lanczos,unsharp=5:5:0.8:5:5:0.0

━━ สถานะไฟล์ v4 (30 ส.ค. 2026) ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ทุกไฟล์เป็น 2280px แล้ว ยกเว้นสามตัวที่ต้นทางเล็กเกินไปจึงหยุดที่ 1920px
  supertrend-snap-v4.webp   ขยายจาก 960px
  ema200-snap-v4.webp       ขยายจาก 960px
  rejection-block-v4.webp   ขยายจาก 960px

⚠️ ความละเอียดส่วนที่เกินขนาดต้นทางเป็นการรีแซมเปิล ไม่ใช่รายละเอียดใหม่
   lanczos + unsharp ให้ขอบคมกว่าปล่อยให้เบราว์เซอร์ขยายเอง (วัดได้ +24~30%)
   แต่ถ้าอยากได้รายละเอียดจริง ต้องแคปหน้าจอใหม่ที่ความละเอียดสูงกว่าเดิม
   สามตัวข้างบนหาต้นฉบับไม่เจอแล้ว — ตรวจด้วยการจับคู่ภาพกับ media-src/tradingview/
   แล้วไม่ตรงสักไฟล์ ต้องแคปใหม่อย่างเดียว

ไฟล์ชุด v3 เดิมลบออกไปแล้วเมื่อ 30 ส.ค. 2026 หลังยืนยันว่าไม่มีโค้ดไหนอ้างถึง
