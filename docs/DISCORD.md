# ให้ยศ Discord อัตโนมัติ

เมื่อแอดมินอนุมัติสลิป ระบบจะให้ยศในเซิร์ฟเวอร์ Discord ให้สมาชิกเองโดยไม่ต้องทำมือ

ถ้ายังไม่ตั้งค่าตามข้างล่างนี้ ระบบจะไม่พัง — หน้า Discord ในพอร์ทัลจะขึ้นข้อความ
ให้สมาชิกแจ้งชื่อกับทีมงานแทน และการอนุมัติออเดอร์ทำงานปกติทุกอย่าง

## 1. สร้างบอท

1. เข้า https://discord.com/developers/applications แล้วกด **New Application**
2. เมนู **Bot** ทางซ้าย กด **Add Bot**
3. กด **Reset Token** แล้วคัดลอกโทเคนเก็บไว้ (เห็นได้ครั้งเดียว)
4. ในหน้า Bot เปิด **Server Members Intent** ให้ติด (ใช้ค้นหาสมาชิกจากชื่อผู้ใช้)

## 2. เชิญบอทเข้าเซิร์ฟเวอร์

วิธีเร็วที่สุดคือประกอบลิงก์เอง ใส่ Application ID ของบอท (หน้า General Information):

```
https://discord.com/oauth2/authorize?client_id=<APP_ID>&scope=bot&permissions=395405552720
```

เปิดลิงก์ → เลือกเซิร์ฟเวอร์ → Authorize

> ⚠️ **Manage Roles + Manage Channels อย่างเดียวไม่พอ** (เคยเข้าใจผิดจนพัง 28 ก.ย. 2569)
> Discord ไม่ให้บอท **มอบสิทธิ์ที่ตัวเองไม่มี** — ห้องของทีมงานต้องได้ Manage Messages
> กับ Manage Threads ถ้าบอทไม่มีสองอันนี้ สร้างห้องจะได้ `403 Missing Permissions`
>
> เลข `395405552720` คือชุดที่สคริปต์ต้องใช้จริงครบ 13 อย่าง: View Channel ·
> Send Messages · Send Messages in Threads · Create Public/Private Threads ·
> Manage Messages · Manage Threads · Embed Links · Attach Files · Add Reactions ·
> Read Message History · Manage Channels · Manage Roles
> — **ไม่ใช่ Administrator** ให้เท่าที่จำเป็นพอ

ถ้าอยากกดเองทีละช่อง: OAuth2 → URL Generator → Scopes ติ๊ก `bot` → ติ๊กสิทธิ์ตามรายการข้างบน

## 3. สร้างห้องและยศด้วยสคริปต์

เอา Server ID ก่อน: User Settings → Advanced → เปิด **Developer Mode**
แล้วคลิกขวาที่ไอคอนเซิร์ฟเวอร์ → **Copy Server ID**

ใส่ใน `.env` ในเครื่อง (ไม่ต้องขึ้น git — `.env` ถูก ignore อยู่แล้ว)

```
DISCORD_BOT_TOKEN=<โทเคนจากข้อ 1>
DISCORD_GUILD_ID=<Server ID>
```

แล้วรัน

```bash
npm run discord:setup            # ดูแผนก่อน ยังไม่แตะเซิร์ฟเวอร์
npm run discord:setup -- --apply # สร้างจริง
```

สคริปต์สร้างให้ครบตามสเปก

| หมวด | ห้อง | ใครเห็น | ใครโพสต์ |
|---|---|---|---|
| PUBLIC | 👋・start-here · 📢・qvx-updates · 🎁・qvx-promotions · 🏆・qvx-results | ทุกคน | QVX Team |
| QVX MEMBER | 🎫・private-homework | QVX Active + QVX Team | QVX Team (สมาชิกใช้ปุ่มเปิด Ticket) |

ยศ **QVX Team** (ทีมงาน) กับ **QVX Active** (สมาชิกที่ยังไม่หมดอายุ)

จบแล้วมันพิมพ์ค่าที่ต้องเอาไปตั้งในข้อ 4 ออกมาให้เลย ไม่ต้องไปหา Role ID เอง

**รันซ้ำได้เสมอ** — ของที่มีแล้วไม่สร้างซ้ำ แต่สิทธิ์ของทุกห้องจะถูกตั้งใหม่ให้ตรงสเปก
ใครเผลอไปแก้สิทธิ์ในแอป Discord รันอีกรอบก็กลับมาถูก

**ไม่ผูกกับบัญชีใคร** — ทุกสิทธิ์ผูกกับยศเท่านั้น ไม่มีสิทธิ์รายบุคคล ใครได้ QVX Active
เว็บเป็นคนตัดสินจากสถานะสมาชิก โอนเจ้าของเซิร์ฟเวอร์กี่รอบก็ไม่กระทบ (Server ID ไม่เปลี่ยน)

**ลำดับยศ — สคริปต์จัดการให้เองแล้ว** ตอนเชิญบอทใหม่ ยศบอทกับยศที่สคริปต์สร้างจะได้
`position` เท่ากันหมด (1) แล้ว Discord ตัดสินด้วยลำดับการสร้าง — ยศบอทเกิดก่อนจึงอยู่
**ล่างสุด** สร้างห้องแล้วได้ 403 ทันที สคริปต์จึงเช็กก่อนแตะห้องและยกยศบอทขึ้นให้เอง

ถ้ายกไม่ได้ (มีคนลากยศอื่นขึ้นไปเหนือบอททีหลัง) สคริปต์จะหยุดพร้อมบอกให้ไปที่
Server Settings → Roles แล้วลากยศของบอทขึ้นเหนือ QVX Active — ทำแล้วรันใหม่ได้เลย

## 4. ตั้งค่าบน Vercel

ใช้ยศเดียวคือ QVX Active

```bash
vercel env add DISCORD_BOT_TOKEN
vercel env add DISCORD_GUILD_ID
vercel env add DISCORD_ROLE_MEMBER     # Role ID ของ QVX Active จากข้อ 3
```

| ตัวแปร | ค่า |
|---|---|
| `DISCORD_BOT_TOKEN` | โทเคนจากข้อ 1 — **เป็นความลับ ห้ามใส่ในโค้ด ห้ามวางในแชต** |
| `DISCORD_GUILD_ID` | Server ID |
| `DISCORD_ROLE_MEMBER` | Role ID ของ QVX Active |
| `DISCORD_ROLE_MONTH` / `_Q3` / `_H6` / `_YEAR` | **ปล่อยว่าง** — ระบบข้ามตัวที่ว่างเอง ตั้งเมื่ออยากแยกยศตามแพ็กเกจ |

ลิงก์เชิญบนเว็บชี้เซิร์ฟเวอร์ **QuantVisionX** แล้ว (ตรวจ 29 ก.ย. 69) ถ้าจะเปลี่ยน
ต้องแก้ทั้ง env และค่าโดยปริยายใน `src/config/site.ts` — ค่าโดยปริยายที่ชี้ผิดที่
จะไม่มีใครเห็นบน production จนกว่า env จะหาย แล้วตอนนั้นลูกค้าจะถูกพาไปผิดเซิร์ฟเวอร์เงียบ ๆ

```bash
vercel env add NEXT_PUBLIC_DISCORD_INVITE_URL   # ลิงก์เชิญแบบ Expire After = Never
```

ตั้งค่าเสร็จให้ deploy ใหม่หนึ่งครั้ง

## 5. เปิดปุ่ม "เชื่อมต่อ Discord" (แนะนำ)

ไม่ตั้งค่าข้อนี้ระบบก็ใช้งานได้ แต่ลูกค้าต้องไปหาชื่อผู้ใช้ Discord ของตัวเองมากรอก
ซึ่งพลาดบ่อย — คนส่วนใหญ่กรอกชื่อที่โชว์ (display name) ไม่ใช่ชื่อผู้ใช้
ตั้งค่าแล้วลูกค้ากดปุ่มเดียว Discord บอกเราเองว่าเป็นใคร แล้วระบบพาเข้าเซิร์ฟเวอร์
และให้ยศให้เสร็จในครั้งเดียว (เหมือนลิงก์ Telegram ที่ระบุตัวตนให้เลย)

1. ไปที่ https://discord.com/developers/applications → เลือกแอปของบอท → **OAuth2**
2. คัดลอก **Client ID** และกด Reset Secret เพื่อเอา **Client Secret**
3. ในหัวข้อ **Redirects** กด Add แล้วใส่ให้ตรงเป๊ะ
   ```
   https://quantvisionx.com/api/discord/callback
   ```
   Discord ปฏิเสธถ้าไม่ตรงแม้แต่ `/` ท้ายสุด — ต้องตรงกับ `NEXT_PUBLIC_SITE_URL` ที่ตั้งไว้
4. ตั้ง env สองตัว แล้ว deploy ใหม่

```bash
vercel env add DISCORD_CLIENT_ID       # ไม่ใช่ความลับ (= Application ID)
```

ส่วน Client Secret อย่าพิมพ์ลงบรรทัดคำสั่ง มันติดใน shell history และโผล่ใน `ps`
ของทุกโปรเซสบนเครื่อง ก๊อปมาแล้วส่งผ่านไฟล์แทน

```bash
pbpaste > .discord-secret && chmod 600 .discord-secret
node scripts/set-vercel-env.mjs DISCORD_CLIENT_SECRET .discord-secret
rm -f .discord-secret
```

สคริปต์ไม่พิมพ์ค่าออกมา บอกแค่ความยาว (ของ Discord ยาว 32 ตัว) และดักกรณี
ก๊อปผิดของ — ได้ URL หรือ `KEY=value` มาแทน — ให้ก๊อปใหม่ แทนที่จะตั้งค่าผิดเงียบ ๆ

**บอทต้องมีสิทธิ์ Create Invite ด้วย** ไม่ใช่แค่ Manage Roles ไม่งั้นการพาเข้าเซิร์ฟเวอร์
จะถูกปฏิเสธ (ลูกค้าจะเห็นข้อความให้กดลิงก์เชิญเข้าเอง)

ขอสองสิทธิ์จากลูกค้าเท่านั้น: `identify` (รู้ว่าเป็นบัญชีไหน) และ `guilds.join`
(พาเข้าเซิร์ฟเวอร์) — ไม่ได้ขออีเมลและไม่ได้ขออ่านข้อความ มีเทสคุมไว้ที่
`src/lib/__tests__/discord-oauth.test.ts`

## การทำงาน

**ฝั่งสมาชิก (เมื่อตั้งค่าข้อ 5 แล้ว)** — ไปที่ บัญชี → Discord กดปุ่มเดียว
Discord ถามยืนยัน แล้วระบบผูกบัญชี พาเข้าเซิร์ฟเวอร์ และให้ยศตามแพ็กเกจให้ทันที
`state` ที่เซ็นด้วย `NEXTAUTH_SECRET` (อายุ 10 นาที) เป็นตัวกันคนหลอกให้เหยื่อ
ผูกบัญชี Discord ของผู้โจมตีเข้าบัญชีตัวเอง

**ฝั่งสมาชิก (ยังไม่ตั้งค่าข้อ 5)** — เข้า Discord ของเราก่อน แล้วไปที่ บัญชี → Discord
กรอกชื่อผู้ใช้ ระบบจะตรวจว่าอยู่ในเซิร์ฟเวอร์จริงก่อนบันทึก ถ้ามีแพ็กเกจใช้งานอยู่แล้วจะได้ยศทันที

**ตอนอนุมัติสลิป** — `approveOrder` เรียก `ensureDiscordRole` ให้ยศตามแพ็กเกจ
พร้อมถอนยศแพ็กเกจอื่นออกเพื่อไม่ให้ค้างเวลาเปลี่ยนแพ็กเกจ

**ตอนยกเลิกการผูก** — ถอนยศทั้งหมดที่ระบบดูแลออกจากเซิร์ฟเวอร์

ขั้นตอนให้ยศถูกครอบ try/catch ไว้ ถ้า Discord ล่มหรือตั้งค่าผิด **การอนุมัติออเดอร์จะไม่ล้ม**
สมาชิกยังได้สิทธิ์ TradingView และ Telegram ตามปกติ

## แก้ปัญหา

| อาการ | สาเหตุที่พบบ่อย |
|---|---|
| ไม่พบชื่อในเซิร์ฟเวอร์ | สมาชิกยังไม่กดเข้าเซิร์ฟเวอร์ / พิมพ์ชื่อเล่นแทนชื่อผู้ใช้ / ยังไม่เปิด Server Members Intent |
| Discord ปฏิเสธการให้ยศ | ยศของบอทอยู่ต่ำกว่ายศที่จะแจก หรือบอทไม่มีสิทธิ์ Manage Roles |
| ยังไม่ได้ตั้งค่ารหัสยศใน env | ยังไม่ได้ตั้ง `DISCORD_ROLE_MEMBER` และไม่มี role ของแพ็กเกจนั้น |
