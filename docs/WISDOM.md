## ลำดับการทำงาน

1. ลูกค้าอ่านข้อมูลที่ `/wisdom` แล้วเปิดบัญชีผ่านลิงก์แนะนำ
2. ล็อกอิน → `/account/wisdom` → ส่งเลขบัญชีเทรด MT5
   (ต้องกรอก TradingView username ก่อน ไม่งั้นส่งไม่ได้)
3. แอดมินได้แจ้งเตือนใน Telegram → เข้า `/admin/wisdom`
4. แอดมินเข้าไปตรวจในระบบ Wisdom เอง — มีบัญชีจริง · สมัครผ่านลิงก์ QVX · ฝากถึงขั้นต่ำ
5. กด **อนุมัติ** → เรียก `activateMembership` ตัวเดียวกับทางจ่ายเงิน (ยอด 0 บาท ช่องทาง `wisdom`)
   บอท TradingView · Telegram · Discord · การหมดอายุ ทำงานเองทั้งหมด

ตรรกะอยู่ที่ `src/lib/broker.ts` · หน้าจออยู่ที่ `src/app/{wisdom,account/wisdom,admin/wisdom}`

## กันให้สิทธิ์ฟรีเกินที่ควร

ทางนี้ไม่มีเงินเข้า จุดที่พลาดแล้วเสียของจริงคือให้สิทธิ์เกิน ป้องกันไว้ 4 ชั้น
แต่ละชั้นมีเทสต์ใน `uat/broker.uat.ts` ที่ยืนยันแล้วว่าถอดออกแล้วเทสต์ล้ม

| ความเสี่ยง | กันยังไง |
|---|---|
| แอดมินกดอนุมัติซ้ำ (ดับเบิลคลิก / สองคนพร้อมกัน) | จองคำขอเป็น `REVIEWING` ด้วย `updateMany` ก่อน — มีแค่คำขอเดียวที่ชนะ |
| คำขอค้างสองอัน อนุมัติทั้งคู่ได้สองเดือน | เช็คช่วงต่ออายุซ้ำตอนอนุมัติ ไม่ใช่แค่ตอนส่ง |
| บัญชีเทรดเดียวรับสิทธิ์ให้หลายคน | `User.brokerAccountKey` เป็น unique ผูกตอนอนุมัติ ฐานข้อมูลเป็นคนตัดสิน |
| กินที่นั่งโปร 300 คนของคนจ่ายเงิน | ช่องทาง `wisdom` ไม่ใช่รายได้ → ยอด 0 → ไม่มีแถว Payment |

**ผูกเลขบัญชีตอนอนุมัติ ไม่ใช่ตอนส่ง** — ถ้าผูกตอนส่ง ใครพิมพ์เลขบัญชีของคนอื่นก่อนก็จองไว้ได้
แล้วเจ้าของตัวจริงส่งคำขอไม่ได้ (ช่องโหว่แบบเดียวกับที่เจอในระบบผูก Discord)

**อนุมัติตายกลางทาง** — ค้าง `REVIEWING` เกิน 5 นาทีกดอนุมัติใหม่ได้ ถ้าเปิดสิทธิ์พลาดจะคืนเป็น `PENDING` เอง

vercel env add NEXT_PUBLIC_WISDOM_SIGNUP_URL   # ลิงก์สมัครแบบมีรหัสแนะนำของ QVX

`NEXT_PUBLIC_*` ถูกฝังตอน build — ตั้งแล้วต้อง redeploy

## ข้อมูลโบรกบนหน้าเว็บ

อยู่ใน `src/config/brokers.ts` เอามาจากคู่มือเปิดบัญชีของน็อต เฉพาะสเปกบัญชีที่เห็นในภาพหน้าจอจริง
(แพลตฟอร์ม · ตลาด · เลเวอเรจ · ฝากขั้นต่ำ)

**ไม่ใส่คะแนนรีวิวหรือจำนวนผู้ใช้ของโบรก** — เป็นตัวเลขของบุคคลที่สามที่เราตรวจไม่ได้
ขึ้นหน้าเว็บเราแล้วกลายเป็นเราเป็นคนอ้าง

## หน้าตรวจของพาร์ตเนอร์โบรก (`/partner`)

Wisdom **ไม่มี API** ให้เชื่อม (ถามแล้ว 27 ก.ย. 2569) พาร์ตเนอร์ที่เปิดหลังบ้านโบรกได้จึงเป็นคนตรวจให้เรา

**สิทธิ์:** ตั้ง `User.role = "PARTNER"` ให้บัญชีเขา (ผ่าน `npm run admin` หรือแก้ในฐานข้อมูล)
- เข้าได้เฉพาะ `/partner` — เห็นคิวคำขอ ข้อมูลลูกค้าที่ต้องใช้เทียบ (ชื่อ อีเมล เลขบัญชี TradingView) และกดอนุมัติ/ปฏิเสธได้
- **เข้า `/admin/*` ไม่ได้เลย** (redirect) — ไม่เห็นสลิป การเงิน สมาชิกคนอื่น หรือแก้ราคา
  แยก layout กันคนละชั้นโดยตั้งใจ ถ้าเปิด `/admin` ให้พาร์ตเนอร์จะเห็นทุกหน้าในนั้นทันที
- แอดมินยังใช้ `/admin/wisdom` ได้เหมือนเดิม (หน้าเดียวกัน คนละทาง)

**ช่อง "หลักฐานจากโบรก"** รวมสิ่งที่ระบบรู้ของเลขบัญชีนั้น แล้วเทียบให้ 4 ข้อ:
สมัครใต้ลิงก์ QVX · ยอดคงเหลือ ≥ ขั้นต่ำ · ชื่อตรง (ไม่สนลำดับคำ · คนละภาษา = – เทียบเอง)
· อีเมลตรง (เฉพาะเมื่อโบรกบอกอีเมลลูกค้า — Wisdom ไม่บอก ข้อนี้จึงไม่โผล่)
✓ ผ่าน · ✗ ไม่ผ่าน · – ยังไม่มีข้อมูล (ต้องเปิดหลังบ้านโบรกเช็กเอง)

> **ระบบไม่อนุมัติเองอัตโนมัติแม้ครบทุกข้อ** — อีเมลปลอมง่ายกว่าหลังบ้านโบรก คนต้องเป็นคนกดเสมอ
> และ "ยอดคงเหลือ" ใช้ ฝาก − ถอน ไม่ใช่ยอดฝากรวม (ฝากแล้วถอนออกทันทีไม่ควรผ่าน)

**ปุ่ม "บันทึกจากหลังบ้านโบรก"** ใต้เลขบัญชี — พาร์ตเนอร์บันทึกสิ่งที่เห็นเอง (สมัคร/ฝาก/ถอน + ยอด + ชื่อ + อีเมล)
บันทึกครั้งเดียว รอบต่ออายุไม่ต้องเปิดหลังบ้านซ้ำ และทีมเห็นว่าใครตรวจอะไรไว้

## อีเมลแจ้งเตือนจากโบรก (บอทอ่านเมล)

`scripts/broker/mailbot.py` อ่านกล่อง **QVXofficial09@gmail.com** แล้ว POST อีเมลจาก Wisdom เข้า `/api/broker/email`
รันอยู่บน **คอมเฟิร์ส** ที่ `C:\QVXMail` — ย้ายมาจากคอมเบสเมื่อ 30 ก.ย. 2569
(ของเดิมบนคอมเบส `C:\QVXAI\mailbot.py` เลิกใช้แล้ว ไม่เคยได้รัน อย่าเปิดคู่กัน)

- บอท**ไม่ตัดสินอะไรเลย** ส่งอีเมลดิบให้เว็บอ่าน — ตรรกะอยู่ที่ `src/lib/broker-events.ts` ที่มีเทสต์คุม
  แก้ pattern แล้วไม่ต้องขึ้นเครื่องใหม่
- **เปิดกล่องแบบอ่านอย่างเดียว** — ไม่มาร์คว่าอ่านแล้ว ไม่ติดป้าย จำว่าส่งถึงฉบับไหนด้วย UID ใน `mailbot.state.json`
  (รุ่นแรกอ่านเฉพาะอีเมลที่ยังไม่อ่าน แต่กล่องนี้มีคนเปิดอ่านด้วย ใครเปิดก่อนบอทวนถึง ฉบับนั้นหายถาวร)
- ส่งไม่สำเร็จ แยกตามสาเหตุ เพราะข้ามผิดจังหวะ = อีเมลหาย
  - secret ไม่ตรง (401) / เว็บยังไม่เปิดรับ (503) / เน็ตหลุด = **รอ ไม่ข้ามอีเมล** แก้แล้วส่งต่อได้ครบ
  - เว็บบอกว่าฉบับนี้ใช้ไม่ได้ (400 / 413 / 422) = ข้ามฉบับนั้น
  - อ่านฉบับนี้ไม่ได้ หรือเว็บล่ม 5xx = ลองใหม่ เกิน 180 รอบ (~6 ชม.) ค่อยข้ามพร้อมเขียน log
- อ่าน `mail.env` ใหม่ทุกรอบ — เปลี่ยนรหัสแอปแล้วมีผลรอบถัดไป ไม่ต้องรีสตาร์ต · IMAP มี timeout 60 วินาที ค้างแล้วไม่แข็ง
- เว็บกันข้อมูลซ้ำด้วย Message-ID
- **อ่านไม่ออกก็ไม่ทิ้ง** — เก็บเป็น `UNKNOWN` พร้อมข้อความดิบ และแจ้งเตือนแอดมินทาง Telegram ให้ไปปรับ pattern
- เทสต์: `python -m unittest scripts/broker/test_mailbot.py`

> **บอทรุ่นแรกทำอีเมลหายทุกฉบับ (แก้ 30 ก.ย. 2569)** — ส่งเวลาแบบ `+07:00` แต่ `/api/broker/email` ตรวจด้วย
> `z.string().datetime()` ซึ่งรับแค่ `Z` → เว็บตอบ 400 → บอทถือว่าจบแล้วมาร์คอ่าน ไม่มีอะไรฟ้อง
> ตอนนี้ส่งเป็น UTC ลงท้าย `Z` มีเทสต์คุม · อีกตัวคือ log ที่มี "·" ทำบอทล้มทันทีเมื่อ stdout ถูก redirect
> บน Windows ภาษาไทย (cp874) — บอทบังคับ UTF-8 เองแล้ว

**อีเมลจริงของ Wisdom** (ส่งจาก `info@mail.wisdomtrade.com` · เห็นครั้งแรก 30 ก.ย. 2569) มี 3 แบบ

| หัวข้อ | แปลว่า | ได้อะไร |
|---|---|---|
| ผู้ใช้ใหม่ลงทะเบียนเรียบร้อยแล้ว | สมัครผู้ใช้ใต้ QVX แต่ยังไม่มีบัญชีเทรด | ชื่อ |
| บัญชีธุรกรรมล่างสำเร็จแล้ว | เปิดบัญชีเทรดใต้ QVX | ชื่อ + เลขบัญชี MT5 → ข้อ "สมัครใต้ลิงก์ QVX" |
| ผู้ใต้บังคับบัญชาฝากเงินสำเร็จ | ลูกค้าฝากเงิน | ชื่อ + เลขบัญชี + ยอด USD |

- ใช้ป้ายไทยกับโคลอนตัวเต็ม "：" · ชื่อเรียง "นามสกุล ชื่อ"
- **ไม่มีอีเมลลูกค้า** มีแต่ `admin@wisdomfinancialservice.com` ของบริษัท — รุ่นแรกหยิบอันนี้มาเป็นอีเมลลูกค้า
  หน้าตรวจเลยขึ้น "อีเมลไม่ตรง" กับทุกคน ตอนนี้ข้ามโดเมนของโบรก (`emailDomains` ใน `src/config/brokers.ts`)
- สมัครแล้วยังไม่มีเลขบัญชี (แบบแรก) ไม่แจ้งเตือนแอดมิน ไม่งั้นกลุ่มแอดมินเด้งทุกครั้งที่มีคนสมัคร
- ยังไม่เคยเห็นอีเมลแจ้งถอนเงิน — มาเมื่อไหร่ดู `rawText` ใน `BrokerEvent` แล้วเพิ่มเทสต์
- ตัวอย่างเต็มอยู่ในเทสต์ `src/lib/__tests__/broker-events.test.ts` ชุด "อีเมลจริงจาก Wisdom"
