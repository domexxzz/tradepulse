# วงจรชีวิตสมาชิก (เปิดสิทธิ์ → เตือน → ปิดสิทธิ์)

ทุกช่องทางการจ่ายเงินจบลงที่ฟังก์ชันชุดเดียวกันใน `src/lib/lifecycle.ts`
เพื่อให้สมาชิกได้ของครบเหมือนกันเสมอ ไม่ว่าจะจ่ายด้วยสลิป Stripe หรือแอดมินเปิดให้เอง

## สิทธิ์ที่ผูกกับแพ็กเกจ

| ช่องทาง | เปิดให้ตอนจ่ายเงิน | ปิดตอนหมดอายุ |
|---|---|---|
| อินดิเคเตอร์ TradingView | อัตโนมัติถ้าตั้งบอท ไม่งั้นเข้าคิวแอดมิน | เหมือนกัน |
| ยศ Discord | อัตโนมัติ (ถ้าตั้งบอทและสมาชิกผูกบัญชีแล้ว) | อัตโนมัติ |
| กลุ่มสัญญาณ Telegram | เข้าคิวให้แอดมินเพิ่มเข้ากลุ่ม | เข้าคิวให้แอดมินนำออก |
| อีเมล | ใบเสร็จ | แจ้งหมดอายุ (เตือนล่วงหน้า 3 วันด้วย) |

## การต่ออายุ

ต่ออายุ **ก่อน** หมดวัน ระบบนับต่อจากวันหมดอายุเดิม ไม่ใช่วันที่กด
เช่น เหลือ 5 วันแล้วซื้อรายเดือนเพิ่ม จะได้ 35 วัน ไม่ใช่ 30 วัน

เหตุผล: ถ้าตัดวันที่เหลือทิ้ง ลูกค้าจะเรียนรู้ว่าต้องรอให้หมดอายุก่อนค่อยต่อ
ซึ่งแปลว่าทุกคนจะมีช่วงที่ใช้งานไม่ได้คั่นทุกเดือน

> แพ็กเกจที่จ่ายผ่าน Stripe ไม่ใช้กติกานี้ — Stripe คุมรอบบิลของตัวเองผ่าน webhook

## งานประจำวัน (cron)

`GET /api/cron/expire` ทำสองอย่าง:

1. **ปิดสิทธิ์** แพ็กเกจที่เลยวันหมดอายุ (เฉพาะที่ไม่ได้ผูกกับ Stripe)
2. **เตือนล่วงหน้า** 3 วันก่อนหมดอายุ ทางอีเมล (ส่งครั้งเดียวต่อรอบบิล)

เมื่อทำงานเสร็จจะสรุปผลเข้า Telegram แอดมิน (ถ้าตั้ง `TELEGRAM_ADMIN_CHAT_ID` ไว้)

### ตั้งค่าบน Vercel

```bash
vercel env add CRON_SECRET     # สุ่มค่ายาว ๆ เช่น openssl rand -hex 32
```

ตารางเวลาอยู่ใน `vercel.json` แล้ว — ตั้งไว้ **01:00 UTC = 08:00 น. เวลาไทย** ทุกวัน
Vercel จะแนบ `Authorization: Bearer $CRON_SECRET` มาให้เอง

> ⚠️ **ไม่ตั้ง `CRON_SECRET` = เส้นทางนี้ตอบ 401 ทุกครั้ง และไม่มีอะไรมาปิดสิทธิ์สมาชิกเลย**
> เลือกปิดตายไว้ก่อน เพราะถ้าเปิดโล่งใครก็ยิงให้ระบบไล่ปิดสิทธิ์ได้

### เรียกเองเพื่อทดสอบ

```bash
curl -H "Authorization: Bearer $CRON_SECRET" https://โดเมนจริง/api/cron/expire
```

ผลลัพธ์: `{"ok":true,"expired":2,"reminded":5,"checkedAt":"..."}`

### ใช้ตัวตั้งเวลาอื่นแทน Vercel Cron

เส้นทางนี้รับทั้ง GET และ POST และรับ secret ทาง query string ได้ด้วย
(`/api/cron/expire?secret=...`) เผื่อใช้กับ cron-job.org หรือ GitHub Actions

## แอดมินสั่งเองได้

| ที่ไหน | ทำอะไร |
|---|---|
| `/admin/members` → เปิด/ต่ออายุ | ให้สิทธิ์ฟรี (0 บาท ไม่นับเป็นรายได้) เช่น โอนนอกระบบหรือชดเชย |
| `/admin/members` → ปิดสิทธิ์ทันที | ปิดทุกช่องทางเดี๋ยวนี้โดยไม่รอ cron (คืนเงิน/ผิดเงื่อนไข) |
| `/admin/access-queue` | รายการ "หมดอายุ — รอถอนสิทธิ์" คือคิวที่ cron ตั้งไว้ให้ |
| `/admin/telegram` | รายการ "หมดอายุ — รอนำออก" เช่นเดียวกัน |

## ตรวจสอบว่าระบบทำงานจริง

```sql
-- สมาชิกที่ระบบถือว่ายังใช้งานได้
SELECT "userId", "planCode", "currentPeriodEnd"
FROM "Subscription"
WHERE status IN ('ACTIVE','TRIALING') AND "currentPeriodEnd" > now();

-- ที่ควรถูกปิดแล้วแต่ยังค้าง (ถ้ามีแปลว่า cron ไม่ทำงาน)
SELECT * FROM "Subscription"
WHERE status IN ('ACTIVE','TRIALING')
  AND "stripeSubscriptionId" IS NULL
  AND "currentPeriodEnd" < now();
```
