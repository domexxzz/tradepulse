# ให้สิทธิ์อินดิเคเตอร์บน TradingView อัตโนมัติ

TradingView ไม่มี public API สำหรับเพิ่ม/ลบ username ในสคริปต์ invite-only
วิธีที่ใช้กันคือบอทที่ล็อกอินบัญชีเจ้าของสคริปต์แล้วกดให้ — บอทตัวนั้นรันแยกจากเว็บนี้

**ไม่ตั้งค่า = ทำงานแบบเดิม** แอดมินเพิ่ม username เองผ่านคิว `/admin/access-queue`

## สัญญาการเรียก

เว็บจะยิงไปที่บอทแบบนี้:

```
POST {TV_BOT_URL}/grant
Content-Type: application/json
{"secret": "<TV_BOT_SECRET>", "username": "someone", "days": 30}
```

```
POST {TV_BOT_URL}/revoke
Content-Type: application/json
{"secret": "<TV_BOT_SECRET>", "username": "someone"}
```

บอทต้องตอบกลับเป็น JSON:

```json
{"ok": true}
```

หรือเมื่อไม่สำเร็จ:

```json
{"ok": false, "error": "ไม่พบ username นี้บน TradingView"}
```

> `days` ส่งมาเฉพาะบางกรณี ถ้าบอทไม่รองรับให้เพิกเฉยได้ (ระบบเว็บเป็นคนคุมวันหมดอายุอยู่แล้ว)
> เพดานเวลารอคือ 30 วินาที ถ้าบอทช้ากว่านั้นเว็บจะถือว่าไม่สำเร็จและตกไปเข้าคิวแอดมิน

## ตั้งค่า

```bash
vercel env add TV_BOT_URL      # เช่น https://tv-bot.example.com  (ไม่ต้องมี / ปิดท้าย)
vercel env add TV_BOT_SECRET   # สุ่มยาว ๆ ต้องตรงกับฝั่งบอท
```

## ระบบเรียกบอทตอนไหน

| จังหวะ | เกิดอะไร |
|---|---|
| อนุมัติสลิป / จ่ายผ่าน Stripe สำเร็จ | เรียก `/grant` ถ้าสมาชิกกรอก username ไว้แล้ว |
| สมาชิกกรอก username ทีหลัง | เรียก `/grant` ทันทีถ้ามีแพ็กเกจใช้งานอยู่ |
| cron ปิดสิทธิ์เมื่อหมดอายุ | เรียก `/revoke` |
| แอดมินกดปิดสิทธิ์ทันที | เรียก `/revoke` |

ทุกครั้งที่บอทตอบไม่สำเร็จ ระบบจะบันทึกเหตุผลไว้ในช่อง note ของคิว
แล้วปล่อยให้รายการค้างอยู่ใน `/admin/access-queue` ให้แอดมินทำมือแทน — **ไม่มีทางที่ออเดอร์จะล้มเพราะบอท**

## ความปลอดภัย

- `TV_BOT_SECRET` เป็นความลับ อยู่ใน env เท่านั้น
- บอทควรรับเฉพาะคำขอที่ secret ถูกต้อง และควรจำกัด IP ต้นทางถ้าทำได้
- อย่าเปิดบอทเป็น public endpoint ที่ใครก็เรียกได้ — ใครยิงถูกก็แจกสิทธิ์สคริปต์ได้ฟรี
