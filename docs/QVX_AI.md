# QVX AI

ผู้ช่วยการเทรดในหน้าสมาชิก `/account/ai` — ตอบจาก **AI บนเครื่องบ้าน (คอมเบส, ฟรี)** มี **คลาวด์เป็นตัวสำรอง**
ค้นคลังความรู้ QVX ก่อนตอบ (**RAG**) และเห็น**ข้อมูลกราฟสด**จากอินดิเคเตอร์บน TradingView · ตอบแบบค่อย ๆ พิมพ์ (streaming)
(ย้ายมาจากระบบแยกของน็อตบน Supabase — ใช้คำสั่งของน็อตทั้งก้อน แต่สิทธิ์ ฐานข้อมูล และโมเดลเป็นของเราแล้ว)

## ภาพรวม

```
ลูกค้า ── /account/ai ──► เว็บ (Vercel)
                            │ 1. ตรวจสิทธิ์ + จองโควตา
                            │ 2. RAG: ค้นคลังความรู้ QVX (รันบน Vercel ไม่พึ่งเครื่องไหน)
                            │ 3. ข้อมูลกราฟสด (ตาราง MarketSnapshot ← webhook จาก TradingView)
                            ▼
              ┌──── คำถามความรู้ ────┐          ┌──── คำถามวิเคราะห์กราฟสด ────┐
              │ 1) เครื่องบ้าน        │          │ 1) คลาวด์ (ถ้าตั้งไว้)         │
              │ 2) คลาวด์ (สำรอง)     │          │ 2) เครื่องบ้าน (สำรอง)         │
              └──────────────────────┘          └───────────────────────────────┘
เครื่องบ้าน = คอมเบส: Cloudflare tunnel → gateway (พอร์ต 8790) → Ollama gemma3:12b (RTX 4080)
```

**ทำไมแยกตามชนิดคำถาม** — ทดสอบกับ gemma3:12b จริงแล้ว: คำถามความรู้ + RAG ตอบแม่นมาก
แต่วิเคราะห์กราฟสดพลาดราวครึ่งหนึ่ง (สลับโซน Buy/Sell) · ถ้าไม่ได้ตั้งคลาวด์ เครื่องบ้านตอบทุกคำถาม
(ช่วยด้วยการสรุปข้อเท็จจริงให้ก่อน: โซนไหนอยู่ใต้/เหนือราคา · ใช้มอง Buy หรือ Sell · ตัวเลขราย TF — หลังเพิ่มแล้วตอบถูก 3/3 รอบ)
ปิดการแยกได้ด้วย `AI_MARKET_PREFER=local`

**สลับตัวสำรองเมื่อไหร่** — เฉพาะตอน "ยังไม่ได้ตอบสักคำ": เครื่องบ้านดับ · tunnel ตาย · การ์ดจอไม่ว่าง (gateway ตอบ 503 ทันที)
· ไม่ได้คำแรกใน 25 วินาที · ตอบไปครึ่งทางแล้วพังจะไม่สลับ (กันคำตอบสองแบบปนกัน) แจ้งพังและไม่หักโควตา

## เช็กว่าพร้อมไหม

```bash
curl -s https://quantvisionx.com/api/ai/status
```
`local.up` = เครื่องบ้านรายงานตัวภายใน 5 นาที · `cloud.configured` = มีตัวสำรอง · `market` = ข้อมูลกราฟล่าสุด
(ไม่มี URL เครื่องบ้าน ไม่มี key) · หน้าแอดมิน → สถานะระบบ มีแถว "QVX AI" กับ "ข้อมูลกราฟสดให้ AI"

## ตั้งค่าบน Vercel

| ตัวแปร | จำเป็น | หมายเหตุ |
|---|---|---|
| `TV_BOT_SECRET` | ✅ (มีอยู่แล้ว) | ใช้คุยกับ gateway เครื่องบ้านด้วย — **หมุนเมื่อไหร่ต้องแก้ .env บอทบนคอมเบสด้วย** |
| `OPENAI_API_KEY` | ตัวสำรอง | key ของ xAI (Grok) หรือ OpenAI · ไม่ตั้ง = ไม่มีตัวสำรอง |
| `OPENAI_BASE_URL` | ถ้าใช้ Grok | `https://api.x.ai/v1` |
| `OPENAI_MODEL` | ถ้าใช้ Grok | เช่น `grok-4.3` |
| `MARKET_WEBHOOK_TOKEN` | ข้อมูลกราฟสด | `openssl rand -hex 32` · ต้องตรงกับที่ใส่ในอินดิเคเตอร์ |
| `AI_MARKET_PREFER` | ไม่ต้อง | `local` = คำถามกราฟก็ให้เครื่องบ้านตอบก่อน |

## เครื่องบ้าน (คอมเบส) — `C:\QVXAI`

| ไฟล์ | ทำอะไร |
|---|---|
| `qvx_ai_gateway.py` | ตัวกลาง: เช็ก secret · บังคับ num_ctx 16384 (ค่าเริ่มต้น Ollama 4096 ตัดคำสั่งทิ้งเงียบ ๆ) · การ์ดไม่ว่างตอบ 503 ทันที · แปลง stream เป็นแบบ OpenAI · Python ล้วนไม่ต้องลงอะไร |
| `run-gateway.bat` + `run-hidden.vbs` | เปิด gateway แบบไม่มีหน้าต่าง · log `C:\QVXAI\gateway.log` |
| `botkeeper.ps1` + `keeper-ai.ps1` | keeper ตัวเดียวกับบอท (role `ai`, พอร์ต 8790): ปลุก gateway/tunnel ที่ตาย + รายงาน URL เข้าเว็บทุกนาที · log `C:\QVXAI\keeper.log` |

Scheduled task (เปิดเองตอน login, Interactive only): `QVXAIKeeper` → เรียก `QVXAIGateway` เมื่อพอร์ต 8790 ว่าง
**เครื่องต้องเปิดและ login ไว้** (เหมือนบอท) · Ollama ต้องรันอยู่ (ใช้ร่วมกับ Sentiara — gateway ขอให้ Ollama เก็บโมเดลไว้ 30 นาทีหลังใช้)

ต้นฉบับทุกไฟล์อยู่ในรีโป `scripts/ai/` + `scripts/bot/botkeeper.ps1` — แก้ในรีโปแล้วค่อยก๊อปขึ้นเครื่อง (ไฟล์ .ps1 เซฟ UTF-8 มี BOM)

**ไล่เช็กเมื่อ `local.up` เป็น false**
```powershell
type C:\QVXAI\keeper.log          # register ai FAILED = เว็บไม่รับ (secret ไม่ตรง?) · ไม่มีบรรทัดใหม่ = keeper ตาย
type C:\QVXAI\gateway.log         # FATAL: no secret = หา TV_BOT_SECRET ใน .env บอทไม่เจอ
schtasks /run /tn QVXAIKeeper     # ปลุก keeper (keeper จะปลุก gateway + tunnel ต่อเอง)
curl.exe http://127.0.0.1:8790/health   # ollama:false = Ollama ไม่ได้รัน
```

## ข้อมูลกราฟสด — alert บน TradingView

อินดิเคเตอร์ **QVX AI** (สคริปต์ส่วนตัวของน็อต สร้างจาก BE ตัวเดียวกับที่ขาย + ส่วนส่งข้อมูลตลาด) ส่งตอนแท่งปิด
1. ตั้งค่าอินดิเคเตอร์ หัวข้อ "QVX AI / Market Sync" ใส่ token = `MARKET_WEBHOOK_TOKEN`
2. **ลบ alert เดิมแล้วสร้างใหม่** (alert จำค่าเก่า) · "Any alert() function call" · Webhook `https://quantvisionx.com/api/market/snapshot`

รูปแบบ payload ตรวจแล้วว่าตรงกับ `QVX_AI.pine` ทุกช่อง (schema 1 · timeframes M1–D1 · ค่า null · ~4 KB)
ข้อมูลใช้ได้นานหนึ่งแท่งของกราฟ + 5 นาที (15–65 นาที) · กราฟ M30 ส่งทุก 30 นาที ใช้ได้ 35 นาที
AI แนบข้อมูลกราฟเฉพาะคำถามเรื่องตลาด (คำถามความรู้แนบแล้วโมเดลพูดเรื่องกราฟที่ไม่มีใครถาม) · ไม่มีโค้ด Pine ในรีโป

## โครงสร้างโค้ด

| ไฟล์ | ทำอะไร |
|---|---|
| `src/lib/ai/chat.ts` | prepareAsk (สิทธิ์ · โควตา · RAG · ข้อมูลกราฟ · ประกอบคำสั่ง) → completeAsk / failAsk |
| `src/lib/ai/llm.ts` | เรียกโมเดลแบบ stream · ลำดับเครื่องบ้าน/คลาวด์ · สลับเมื่อพังก่อนคำแรก |
| `src/lib/ai/rag.ts` + `corpus.ts` | ค้น TF-IDF ของตัวอักษร 2-3 ตัว (ใช้กับไทยได้ไม่ต้องตัดคำ) · คลังความรู้จากคู่มือ + ราคา/Wisdom/FAQ สดจาก config |
| `src/lib/ai/instructions.ts` | คำสั่งของน็อต — **ไม่แก้** · `knowledge.ts` = แกนความรู้ + ความหมายช่องข้อมูลกราฟ |
| `src/lib/ai/market.ts` | รับ/ตรวจ webhook · สรุปข้อเท็จจริง (โซนใต้/เหนือราคา · ตัวเลขราย TF) |
| `src/lib/ai/gateway.ts` | สถานะเครื่องบ้าน/คลาวด์ |
| `src/app/api/ai/chat` · `status` · `market/snapshot` | API |

ตาราง: `AiConversation` · `AiMessage` (มี `sources` = หัวข้อที่อ้างอิง) · `AiUsage` · `MarketSnapshot` · `BridgeEndpoint` (role `ai`)

แก้คลังความรู้: `corpus.ts` — ชิ้นหนึ่งหนึ่งเรื่อง ใส่คำที่ลูกค้าพิมพ์จริง แล้วเพิ่มคำถามใน `src/lib/__tests__/rag.test.ts`
**ห้ามใส่ผลตอบแทน/อัตราชนะ/ผล backtest** (โค้ดอินดิเคเตอร์มีคอมเมนต์ WR/PF — ห้ามยกมา) มีเทสต์กันไว้
